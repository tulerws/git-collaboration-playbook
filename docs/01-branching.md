# Branching

Create short-lived branches from an up-to-date default branch.

- Use a searchable prefix such as `feature/`, `fix/`, or `docs/`.
- Keep one clear objective per branch.
- Rebase or merge the default branch before requesting final review.
- Delete the branch after the pull request is merged.

A branch name should explain intent without requiring the issue to be opened,
for example `fix/session-timeout` instead of `changes-2`.
